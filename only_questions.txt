## Question 1: Linux Process Priority and Resource Management
**Topic:** Linux Fundamentals, Resource Management
**Difficulty:** Intermediate
**Time Estimate:** 15-20 minutes

In Linux, the Nice command is used to prioritize the execution of processes.

**Part a.** Explain how nice values work (range, priority levels) and provide a real-world example from your project where you would use process prioritization.

**Part b.** If you need to prioritize specific workloads in a Docker or Kubernetes environment, how would you achieve similar functionality to the native Nice command of Linux?

**Skills Tested:** Linux internals, process management, container resource management, Kubernetes resource requests/limits

## Question 3: Kubernetes Probes Implementation
**Topic:** Kubernetes, Application Health Management
**Difficulty:** Intermediate
**Time Estimate:** 20-25 minutes
**Prerequisites:** Understanding of pod lifecycle, basic K8s deployments

What are the Kubernetes probes (startup, readiness, liveness) that you have used in your deployments? For each probe type you've implemented:
- Explain its specific purpose and importance
- Describe the prerequisites and configuration requirements
- Provide implementation examples

**Follow-up Questions:**
1. What are the check mechanisms that you used while implementing the probes apart from httpGet? (e.g., tcpSocket, exec)
2. Probes seem very useful. Why doesn't Kubernetes mandate applications to have default probes? Why are startup, readiness, and liveness probes all optional?

**Common Pitfalls to Avoid:**
- Not explaining the resource cost of running probes
- Confusing the purpose of different probe types
- Assuming probes are always necessary regardless of application type

**Skills Tested:** K8s probes, application health checks, production readiness

## Question 5: Kubernetes Application Dependency Management
**Topic:** Kubernetes, Application Architecture, HA Design
**Difficulty:** Advanced
**Time Estimate:** 30-40 minutes
**Prerequisites:** Init containers, probes, service dependencies, GitOps concepts

**Scenario:** Design a Kubernetes deployment setup where you have 3 applications that need to run in High Availability (HA) to create a solution. The applications have strict starting and running dependencies:

a. Application 1 should always start first
b. Application 2 should always start after Application 1 is Ready
c. Application 3 should always start after Application 2 is Ready

**Follow-up Questions:**
1. How will you design a check mechanism for the applications in such a way that restarts and scheduler reschedules don't break the dependency requirements?
2. How will you plan to incorporate such check mechanisms with CD tools where deployments are GitOps-driven?

**Expected Answer Structure:**
- Architecture approach (init containers, probes, readiness gates)
- YAML configuration strategy
- Handling edge cases (pod restarts, node failures, rescheduling)
- GitOps integration and automation
- Testing and validation approach

**Skills Tested:** Advanced K8s patterns, init containers, dependency management, GitOps, production architecture

## Question 7: Multi-Tier Application Resource Planning
**Topic:** Resource Management, Architecture Design, Cost Optimization
**Difficulty:** Advanced
**Time Estimate:** 25-30 minutes

**Scenario:** You have 3 applications that make a complete solution:
- **UI application:** 100MB memory, 1 CPU
- **Business application:** 200MB memory, 2 CPU
- **Database application:** 300MB memory, 3 CPU
- **Scaling ratio:** 1:2:3 for every 1000 users

All three applications are installable standalone and connect with one another via configurations and endpoints. The resource ratio of 1:2:3 must be maintained during scaling.

**Main Question:** How will you design and deploy the solution on the following infrastructures while maintaining the resource ratios?
1. On Virtual Machines (VMs)
2. On Docker setup
3. On Kubernetes setup

**Follow-up:** Design the most optimal solution, keeping production cost as the top priority. Consider:
- Auto-scaling capabilities
- Resource efficiency
- Operational overhead
- Cost per user

**Skills Tested:** Resource planning, architecture design, scaling strategies, cost optimization

## Question 8: Kubernetes Platform Update Strategy
**Topic:** Platform Management, Upgrade Strategies, Risk Management
**Difficulty:** Advanced
**Time Estimate:** 25-30 minutes
**Prerequisites:** K8s cluster architecture, node management, understanding of K8s version compatibility

One of the main activities for a DevOps engineer is to maintain the software versions of the platform. However, updating the platform without downtime or customer impact is hard to achieve.

**Main Questions:**
- How are you currently updating your Kubernetes platform?
- How would you design an update strategy for a Kubernetes platform in production?

**Follow-up Questions:**
1. How do you plan for fail-safe migration? For example, what if during the update, the upgrade makes the platform unstable or unresponsive?
2. When migrating from version X to version X+1, how will you evaluate that the plugins (network, storage, daemons) won't break the upgrade?

**Expected Discussion Points:**
- Upgrade strategies (in-place, blue-green cluster, rolling node updates)
- Testing and validation procedures
- Rollback plans
- Compatibility matrix verification
- Backup and disaster recovery
- Communication and change management

**Skills Tested:** Platform management, upgrade strategies, risk mitigation, production operations
